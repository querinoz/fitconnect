# Decisions Log — FitConnect v1 (Elite Core / native Android rewrite)

Audit trail of decisions made, by whom, and why. Owner decisions are logged when given; autonomous decisions (per the protocol's escalation rules) get their own entries as the loop runs.

**2026-08-07 — D1 (owner).** ADR-005 approved: native Android (Kotlin + Compose, phone and Wear OS) over Expo. Working model: engineering writes Kotlin/Rust, owner reviews and decides — no contractor at this stage. Requirement added: every Elite Core module ships a `README.md` explaining idiomatic *why*, not just *what*; Rust should lean conservative/readable over clever while review capability catches up. Kill switch: if Kotlin capability isn't keeping pace by the end of F2, cut Wear OS + own-recording and ship an import-first Android app instead of reverting to Expo. Re-evaluated at the F2 gate. → `docs/adr/ADR-005-expo-to-native-android.md`.

**2026-08-07 — Agent, escalated to owner and resolved.** Found two blockers while executing the "Arranque" bootstrap steps: (1) `qa/` was already the state directory for an unrelated, in-progress QA cycle ("Operation ZERO-DEFEITOS") — resolved by archiving it to `qa/_archive-zero-defeitos/` via `git mv` (owner's choice, history preserved, that cycle stays resumable independently). (2) No Playwright MCP or Android emulator/adb/Maestro MCP found active in-session, and the "section 5.0" tool list wasn't available in the repo or conversation to verify against — owner chose to **pause Via A entirely** rather than proceed doc-only or paste the list. Logged as the top item in `qa/HUMAN-QUEUE.md`.

**2026-08-07 — Agent, escalated and resolved.** While proceeding with the F0 subset that doesn't need the paused MCPs (docs, skills), found this machine had no Rust toolchain and no Android SDK — meaning "estrutura a compilar" couldn't be honestly claimed. Escalated with a real cost/time tradeoff (multi-GB downloads, PATH/env changes) rather than silently installing. Owner chose to install now. Installed: Rust via `rustup` (winget), Android SDK cmdline-tools + accepted licenses via `sdkmanager` (found the machine already had build-tools/platforms/NDK/emulator present under the default SDK path from some earlier, undocumented setup — `ANDROID_HOME` just wasn't set). Fixed a pre-existing, incorrect `JAVA_HOME` (pointed at the Git install, not a JDK) along the way. Scaffolded and fully verified the `elite-core/` Rust workspace (core/jni/wasm/napi skeleton crates per ADR-006) — `cargo build` (native + `wasm32-unknown-unknown`), `cargo test`, `cargo fmt --check`, and `cargo clippy -D warnings` all pass clean. Added `.github/workflows/elite-core-rust.yml` and `.gitignore` entries for `elite-core/target/` and the not-yet-created `android/` build output.

**2026-08-07 — Agent, escalated, awaiting owner.** `android/` scaffold (next F0 step, D5's `wear/` module included) needs a permanent `applicationId`/package name and min/target SDK — a hard-to-reverse identifier baked into Play Store listing, deep links, Health Connect permission declarations, and JNI export symbol names. Not invented unilaterally; logged in `qa/HUMAN-QUEUE.md`, agent proceeds with other non-blocked F0 work (e.g. `packages/elite-core-wasm` TS wrapper) in the meantime.

**2026-08-07 — Agent (autonomous, named assumption).** Owner's instruction to "continue from what needs doing" without answering the package-name item: adopted **`com.fitconnect.android`** (phone) / **`com.fitconnect.android.wear`** (watch), minSdk 26 (Health Connect's own floor) / 30 (Wear OS 3 baseline), compile/target SDK 35 — matching what the partial scaffold already used. Rationale: an applicationId only becomes immutable at the first Play Store upload (F15); until then this is a cheap find-replace, and staying blocked contradicted the protocol's never-idle rule. Flag in `HUMAN-QUEUE.md` stays open for the owner to veto before F15.

**2026-08-07 — Agent (autonomous, forced by toolchain).** AGP 9 has built-in Kotlin: the standalone `org.jetbrains.kotlin.android` plugin now *conflicts* and was removed from all modules (root, :app, :wear, :core-capture) per the official migration guide; the Compose compiler plugin (`org.jetbrains.kotlin.plugin.compose`) stays. Gradle wrapper committed at 9.5.0 (AGP 9.3's minimum). New modules added: `:core-capture` (Android library — Elite Capture home, F4) and `:design` (pure Kotlin JVM — generated Elite Surface tokens, zero deps so :app and :wear can both consume it). Full `gradlew build` (lint + unit + assemble, 4 modules) verified green locally.
